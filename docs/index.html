Manual de Transição Técnica — Melhora+

Documentação integral de arquitetura, funcionalidades, migração e infraestrutura para novos desenvolvedores.

Visão Geral & Arquitetura

O Melhora+ é uma plataforma agrícola de unificação e processamento de dados genéticos bovinos. O sistema resolve a fragmentação de relatórios fornecidos por diferentes associações pecuárias (ANCP, PMGZ e Geneplus), oferecendo um dashboard consolidado, análises estatísticas intra-rebanho e geração de relatórios em formato PDF customizado para proprietários rurais.

Arquitetura Consolidada do Sistema

Uma arquitetura de três camadas moderna e escalável, projetada para desacoplamento completo.

Frontend Web

Next.js 15 (App Router) TailwindCSS Design System Hospedado no Vercel
HTTP / JSON

Backend REST API

FastAPI (Python) SQLAlchemy 2.0 ORM Hospedado no Render / Railway
TCP / SSL

Banco de Dados

PostgreSQL (Neon.tech) Esquema Multi-tenant Serverless / Auto-scaling

Camada de Apresentação (Frontend)

Interface responsiva de alta densidade desenvolvida em Next.js 15 e estilizada com o Agro-Centric Design System. Consome a API do backend de forma assíncrona, gerenciando sessões de usuário via Tokens JWT.

Camada de Serviços (Backend)

API REST robusta baseada em FastAPI que gerencia o processamento assíncrono de arquivos pesados (.xlsx/.xls), efetua conversão e limpeza de colunas pecuárias e gera relatórios gráficos complexos de forma otimizada.

💡
Estrutura de Multi-Tenancy: O banco de dados é estruturado para suportar múltiplas fazendas com dados isolados logicamente. Cada registro pecuário está atrelado a um ID de Fazenda (id_farm), garantindo privacidade total.

Funcionalidades do Sistema

O ecossistema Melhora+ é centrado no tratamento de planilhas pecuárias e análises genéticas complexas. Abaixo estão as principais funcionalidades implementadas:

1. Módulo de Upload & Processamento Genético Assíncrono ▼

O usuário faz o upload de planilhas originais de associações pecuárias. O motor do backend (backend/processor.py) executa:

  • Deduplicação Inteligente: Cálculo de hash do arquivo (SHA-256) para evitar re-processamento.
  • Mapeamento Dinâmico de Colunas: A plataforma traduz cabeçalhos customizados das planilhas para a tabela mestre silver.animais sem necessidade de alterar o código (as regras são guardadas na tabela ColumnMapping).
  • Validação de Dados: Filtro automático de tipos de dados errados, datas fora de escopo pecuário ou sexagem inconsistente.
2. Análise Intra-Rebanho (Intra-Herd Processor) ▼

Gera cálculos estatísticos de ranqueamento interno e distribuição percentil das avaliações genéticas de um lote ou fazenda específica:

  • Distribuição de pesos à desmama (P210), ano (P365) e sobreano (P450).
  • Índices de fertilidade (IPP) e carcaça (AOL, EGP).
  • Ranqueamento por percentil pecuário, organizando os animais em categorias elites.
3. Motor de Relatórios Customizados (PDF Generator V2) ▼

Construído sobre a biblioteca ReportLab e Matplotlib, o gerador monta relatórios em PDF de alta qualidade gráfica contendo:

  • Gráficos de dispersão e histogramas da qualidade genética da fazenda.
  • Comparativo de evolução entre safras anteriores.
  • Listagem formatada dos melhores reprodutores e matrizes da propriedade.
  • O relatório é gerado em tempo de execução via API Stream de dados, reduzindo o consumo de memória RAM no servidor.
4. Dashboard Agro & Benchmarking Inter-Fazendas ▼

Painel gerencial que consolida os KPIs gerais da conta:

  • Total de animais ativos divididos por raça e sexo.
  • Comparativo de pontuações de DEPs/EPDs entre diferentes propriedades do mesmo dono.
  • Histórico detalhado de processamento com relatórios de logs para fácil manutenção pelo produtor.

Configuração de Contas para Transição

Para transferir o projeto para uma nova equipe de engenharia sem perdas, siga o checklist de criação e migração de contas externas:

Passo 1: Organizar e Configurar o GitHub ▼

A equipe precisará de uma conta no GitHub para receber o código-fonte.

  1. Acesse GitHub e crie uma conta institucional/organizacional ou pessoal para o novo responsável.
  2. Para clonar o projeto atualmente: 
    git clone git@github.com:kauanmassuia14/melhoramais.git
  3. Transferência do Repositório: Vá em Settings > Danger Zone > Transfer ownership no repositório do GitHub e envie para o novo nome de usuário ou organização criada.
  4. Configurar GitHub Pages: Se desejar manter esta página de documentação ativa no GitHub Pages do repositório:
    • Vá em Settings > Pages.
    • Em "Build and deployment", selecione o branch principal (ex: main ou feat/byanka) e escolha a pasta /docs.
    • Clique em Save. O manual ficará público no link https://[seu-usuario].github.io/melhoramais/.
Passo 2: Configurar o Neon.tech (Banco de Dados PostgreSQL) ▼

O banco de dados de produção está hospedado na plataforma serverless Neon.tech. Para configurar um novo banco:

  1. Acesse Neon.tech e crie uma conta gratuita ou plano Team.
  2. Crie um novo projeto chamado melhoramais-agro. Selecione a região preferencialmente mais próxima de onde sua API estará hospedada (ex: AWS US East ou AWS South America/São Paulo para menor latência).
  3. Vá para o painel principal, copie a connection string do PostgreSQL (formato postgresql://neondb_owner:...@ep-cool-resonance-...).
  4. Certifique-se de salvar essa string temporariamente. Ela será configurada como a variável de ambiente DATABASE_URL no seu servidor.
Passo 3: Configurar Plataformas de Hospedagem (Render / Railway / Vercel) ▼

O projeto está dividido em duas partes hospedadas de forma independente:

  • Frontend (Next.js): Recomendamos hospedar na Vercel devido ao suporte nativo para Next.js App Router e otimização de imagens de forma transparente.
  • Backend (FastAPI): Pode ser migrado para o Render ou Railway. O Render oferece planos gratuitos/econômicos excelentes para APIs Python rodando em contêineres Docker ou direto por scripts Python.

Guia Prático de Migração para o Render

Se você precisa desativar a conta atual no Railway e migrar o backend de forma simples para a plataforma Render.com, siga os passos abaixo:

Passo 1: Criar o "Web Service" no Render ▼
  1. Entre no seu painel da Render e clique em New + > Web Service.
  2. Conecte sua conta do GitHub e selecione o repositório melhoramais.
  3. Configure as opções básicas do Web Service:
    • Name: melhoramais-backend
    • Environment: Python 3
    • Region: Selecione a mesma região do banco de dados Neon para evitar latência.
    • Branch: Escolha a branch de produção estável (ex: main).
Passo 2: Configurar Comandos de Build & Start ▼

Como a nossa estrutura de arquivos coloca a API FastAPI sob a pasta de origem, configure os comandos da seguinte forma:

Build Command: 
pip install -r backend/requirements.txt
Start Command: 
python -m uvicorn backend.main:app --host 0.0.0.0 --port $PORT
Passo 3: Adicionar as Variáveis de Ambiente no Render ▼

No menu lateral esquerdo do Render, clique em Environment e adicione as seguintes chaves:

Variável (Key) Valor Exemplo / Descrição
DATABASE_URL String de conexão obtida no Neon PostgreSQL (certifique-se de usar o prefixo postgresql://).
JWT_SECRET Uma string aleatória em formato hexadecimal para encriptar os tokens JWT de login.
ALLOWED_ORIGINS Link do frontend hospedado na Vercel (ex: https://melhoramais-edfn.vercel.app) para evitar bloqueios de CORS.
Passo 4: Executar as Migrações e Criar o Esquema no Novo Banco Neon ▼

Quando a API rodar pela primeira vez no novo banco de dados Neon, as tabelas estarão vazias. Para criar a estrutura automaticamente:

  1. Configure temporariamente o arquivo local .env com a DATABASE_URL do novo banco Neon.
  2. Execute o script de criação de esquema: 
    python backend/create_schema.py
  3. Rode os scripts adicionais de migração na pasta do backend caso precise estruturar novos campos adicionados nas últimas sprints.
Passo 5: Atualizar a URL da API no Frontend (Vercel) ▼
  1. Acesse o painel da sua aplicação frontend na Vercel.
  2. Vá em Settings > Environment Variables.
  3. Altere o valor de NEXT_PUBLIC_API_URL para o endereço HTTPS fornecido pelo Render (ex: https://melhoramais-backend.onrender.com).
  4. Redesloque a aplicação (Redeploy) na Vercel para aplicar a alteração nas páginas estáticas de build.

Status do Projeto & Handoff

Lista do estado real de implementação de cada componente do sistema na data de hoje (Agosto/2026):

Pronto / Funcional

O que está pronto:

  • Autenticação de Usuário e Controle de Níveis (Admin vs. Fazendeiro).
  • Parser de planilhas ANCP, PMGZ e Geneplus.
  • Salvamento de Mapeamentos de Colunas dinamicamente por Fazenda.
  • Consulta completa e avançada de Animais com filtros.
  • Estrutura de Multi-tenant implementada na API.
  • Geração básica de relatórios PDF.
Em Desenvolvimento / Melhorias

O que precisa de atenção:

  • Análise Intra-rebanho: A lógica de processamento estatístico foi adicionada ao backend (backend/intra_herd_processor.py), mas necessita de validação com dados reais de campo.
  • Os componentes de interface para a Análise Intra-rebanho estão no Git na pasta frontend/src/app/analise-intra-rebanho/ mas precisam de homologação final.
  • Exportação avançada de gráficos complexos no PDF (ocasionalmente consome muita memória na geração assíncrona).

Pontos a Melhorar

  • Caching de Consultas: A tabela de animais cresce exponencialmente. Adicionar paginação estrita no frontend e Redis cache para listagem de animais.
  • Tratamento de Arquivos Grandes: Uploads de arquivos XLSX com mais de 50.000 linhas devem ser migrados para tarefas assíncronas em background real (ex: Celery + Redis) ao invés de rodar na thread principal da request FastAPI.
  • Interface Mobile: Embora a tabela pecuária seja responsiva, a experiência do produtor no celular ao carregar mapeamentos de planilhas complexas pode ser melhorada com fluxos simplificados (Wizard guiado).

Próximos Passos Sugeridos

  1. Implementar rotinas de testes automatizados na pasta tests/ para validar a integridade dos parsers de planilha genérica contra novos layouts de relatórios das associações.
  2. Concluir a integração visual da tela de Análise Intra-Rebanho para exibir os gráficos estatísticos de curva de distribuição Gaussiana dos animais.
  3. Habilitar backup diário automático (Point-in-time recovery) no painel do Neon PostgreSQL.

Variáveis de Ambiente & Comandos Úteis

Guia rápido de referência de comandos para setup local de novos desenvolvedores:

Configuração de Desenvolvimento Local

Para rodar o backend localmente com o banco de desenvolvimento local (SQLite):

# Instalar dependências (dentro da pasta backend)
pip install -r requirements.txt

# Iniciar servidor de desenvolvimento local
python -m uvicorn backend.main:app --reload --port 8000

Para rodar o frontend localmente:

# Instalar pacotes (dentro da pasta frontend)
npm install

# Rodar servidor Next.js
npm run dev

Variáveis de Ambiente Recomendadas (Local)

Crie um arquivo .env na raiz do backend:

DATABASE_URL=sqlite:///./test.db
JWT_SECRET=crie-um-segredo-longo-aqui
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:3001

Crie um arquivo .env.local na raiz do frontend:

NEXT_PUBLIC_API_URL=http://localhost:8000
